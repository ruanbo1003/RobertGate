# 投资报告 Agent（投资建议书 / 尽调报告）PRD

## 概述

一个从范本学习到成稿导出的投资报告写作 Agent 工作台：学习历史报告的格式与写法 → 消化标的资料并联网研究 → 分章节生成带溯源的 60 页量级初稿 → 对话式精修与段落重写 → 导出干净的 Word 成稿。

## 目标用户

- **用户画像**：Robert 本人（投资经理，VC/PE/并购，一级市场股权，标的以国内公司为主），单用户
- **核心诉求**：
  - 资料搜集、行业/竞品分析、初稿写作全流程交给 Agent，自己只做判断与精修
  - 初稿必须沿用自己历史报告的结构与文风（约 10 份范本，格式大致一致但不完全统一）
  - 编辑时每个关键事实/数字可查出处，杜绝凭空捏造；导出稿不带引用（引用只服务于核稿）
  - 精修可通过对话、段落级重写、补传资料/URL 增量更新完成

## 使用场景

1. **立项初稿**：收到标的 BP 与基本资料，上传 → Agent 按建议书模板逐章研究并成稿（含投资建议结论章）→ 逐段精修 → 导出 Word 上会。
2. **尽调报告**：尽调过程中陆续上传访谈纪要、财务明细、天眼查导出件 → Agent 结合联网核查成稿（含分级风险清单章）→ 补传新资料触发受影响章节更新。
3. **系列化产出**：同一模板连续做多个标的，格式始终一致，不再手调 Word 样式。

## 功能需求

### P0（必须实现）

**模块一：范本库与模板学习**
- [ ] 历史报告分批上传（.docx），按类型归档：投资建议书 / 尽调报告
- [ ] 「学习生成模板」：选中若干范本 → Agent 归纳出模板档案——章节骨架、各章写作要点、数据呈现习惯、样式规范（标题层级/表格样式）；范本间差异归纳共性并标注分歧供选择；单份范本也可学习（降级为单范本提取）
- [ ] 模板档案可查看、可手动微调（章节增删改名、要点编辑）；两类报告各自独立
- [ ] **硬门槛**：对应类型的模板未学习时，不允许创建该类型报告项目（引导去范本库）

**模块二：报告项目与资料库**
- [ ] 新建项目：选类型（建议书/尽调）+ 模板 → 进入工作台
- [ ] 资料清单引导：新建后提示建议上传的资料（BP、财务表、**天眼查导出的工商信息/股权结构/涉诉记录页**——天眼查为网页版账号，走"导出/截图上传"而非 API）
- [ ] 资料库：项目内统一管理，支持 .docx / .pdf / .xlsx / 图片（png/jpg）；扫描 PDF 与图片用多模态模型解析（OCR）；随时补传；解析后可预览；损坏/无法解析的单文件标红不影响其他
- [ ] 项目列表页：卡片网格（报告名、类型徽章、整体进度环、更新时间）

**模块三：Agent 研究与写作（异步）**
- [ ] 逐章独立状态机：待研究 → 研究中 → 已完成 / 失败 / 已过期；失败单章重试不连坐；关闭页面后台继续
- [ ] 研究手段：上传资料解析提取 + **OpenRouter 联网检索**（`:online` / web 插件，结果自带来源 URL，无需第三方搜索 Key）
- [ ] 研究进度流实时可见：Agent 动作逐条滚动（在查什么/查到什么/从哪份资料第几页取数），每条可点开看原文
- [ ] **强溯源**：正文关键事实/数字带引用角标 `[n]`，hover 出处摘要（来源+关键句+日期），点击右栏定位；时效敏感数据（估值、融资轮次）标注"截至 YYYY-MM"
- [ ] **反捏造**：查无依据的数据位不落数字，显示黄色「待补充」胶囊（hover 说明缺什么），可人工填值并标注"人工提供"
- [ ] 类型差异：建议书末章为投资建议结论（投/不投/条件投+理由）；尽调末章为分级风险清单（高/中/低）

**模块四：精修工作台（核心页，三栏混搭布局）**
- [ ] 左栏章节树（每章状态点）；中栏编辑器（`max-w-[760px]` 居中，接近成稿排版，正文直接编辑）；右栏 Tab：Agent 对话 / 研究进度 / 本章引用列表（默认停在进度，全章完成后自动切对话）
- [ ] 段落级重写：选中段落 + 指令 → Agent 重写该段直接落稿（不做 diff 预览），其他段不动
- [ ] 对话式修改：右栏对话全文或指定章节，修改直接应用
- [ ] 增量更新：补传资料/贴 URL → Agent 给「影响分析卡」（建议更新章节+理由）→ 勾选确认后更新，相关章节标"已过期→更新中"；命中正在编辑的章节时弹确认
- [ ] 通读模式：隐藏左右栏，全文连续滚动只读预览

**模块五：导出**
- [ ] 导出 .docx：按模板样式（标题层级、字体、表格）；**干净稿**——不含引用角标、不含参考资料清单、「待补充」占位需清零或人工确认后方可导出

### P1（暂不做，仅记录）

## 交互设计

- **加载态**：章节未生成→骨架屏+本章研究计划预览；列表页骨架卡
- **空状态**：范本库空→引导上传第一批范本；项目列表空→引导先学模板再建项目；模板未学→新建按钮禁用+提示
- **错误态**：章节研究/生成失败→失败态+可读错误+单章重试；上传解析失败→单文件标红；上游配额错误→全局暂停提示（沿用 ai-videos 队列语义）
- **关键交互**：引用角标 hover/点击定位；段落 hover 出「重写」；影响分析卡勾选确认；研究动作条目点开看原文；导出前「待补充」清零校验

## 边界情况

- 范本仅 1 份：可学习，降级为单范本提取
- 增量更新命中正在编辑的章节：确认弹窗，基于最新保存版更新
- 扫描件/图片解析置信度低：资料标"解析质量低"，引用该来源时出处卡带提示
- 60 页长文：逐章生成与渲染，通读模式分段懒加载
- 检索无结果/来源互相矛盾：正文留「待补充」，研究流记录矛盾点供人工裁决

## 设计约束

遵循 `.claude/rules/ui-style.md`：primary `#2563EB`（章节状态、引用角标、Agent 按钮）、accent `#EA580C`（「待补充」警示用 error/warning 色系）、卡片 16px 圆角+轻阴影、Plus Jakarta Sans（中文 fallback 系统字体）、禁止硬编码色值、空/载/错三态不可省。

## 技术备注

- **Agent 框架（Robert 2026-11-06 拍板）**：**Pydantic AI**（内层）+ 自家队列模式（外层编排，沿用 ai-videos 的逐章异步/失败不连坐/配额暂停语义）。
  - 两个 Agent：①「章节研究写作 Agent」——工具 `web_search` / `read_url` / `query_sources`（查上传资料）/ `extract_table`，输出为 pydantic 定义的结构化章节（正文 + claim→citation 绑定，校验不过自动重试）；②「对话修改 Agent」——工具：读章节 / 改段落 / 触发重研究。
  - 模板学习不走 Agent，一次结构化抽取调用即可。
  - **web 检索必须是显式工具**（内部调 OpenRouter web 插件取带 URL 结果），不得把写作请求整体挂 `:online`——保证每次检索成为可记录/可回放的研究动作，支撑进度流与溯源。
  - Pydantic AI 的事件流钩子对接「研究进度 Tab」；依赖注入对接 DDD 的 uow/storage port。
  - 新增依赖：`pydantic-ai`（置于 infrastructure 层，domain/application 不感知）。
- **LLM/检索**：全部走 OpenRouter（现有 `OPENROUTER_API_KEY`）；联网检索用 OpenRouter web 插件（`:online`，约 $0.004/次，返回带 URL 的引用）；图片/扫描 PDF 用多模态模型（Gemini 系）解析
- **异步**：复用 ai-videos 的进程内队列模式（逐章任务、失败不连坐、配额暂停、关页续跑）
- **文档解析**：.docx（python-docx）、.pdf（文字版直提/扫描版走多模态）、.xlsx（openpyxl）
- **导出**：python-docx 按模板样式生成；不含引用与脚注（引用仅存编辑态数据库）
- **数据模型（草案）**：范本（sample）、模板档案（template，含章节骨架 JSON）、项目（report）、章节（chapter，状态机）、资料（source，解析产物）、引用（citation：chapter_id/锚点/来源类型/URL 或 source_id+页码/摘要/抓取日期）、对话（chat）
- **API**：统一 `/api/v1/invest-reports/*`，RESTful，返回格式遵循 `.claude/rules/api.md`
- 天眼查：无 API，依赖用户从网页版导出 PDF/截图作为上传资料，解析后视作高可信来源
