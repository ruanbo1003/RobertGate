# why-video：小朋友科普视频生成 skill 设计文档

日期：2026-10-27
状态：待 Robert 批准

## 意图与背景

Robert 家有 4-8 岁的小朋友，日常对话中会不断冒出"为什么"问题（"地球为什么是圆的"）。
这个 skill 把一个这样的问题变成一条**可以在手机上播放、可直接发布到自媒体（抖音/视频号等）
的竖屏科普短视频**：先联网查证科学解释，再写成孩子听得懂的旁白脚本与分镜，
经 Robert 过目确认后，调用 AI 视频生成与 TTS 合成最终 MP4。

核心价值：把"查资料 → 写稿 → 做视频"的几小时工作压缩成一条命令 + 一次脚本确认。

## 目标

- 一条命令启动：`/why-video <问题>`。
- 内容科学准确（联网搜索、交叉核对），语言适合 4-8 岁儿童：有引导、铺垫、比喻，讲故事的语气。
- 画面是**连续的视频镜头**（AI 生成的真实感视频片段），不是静态图片轮播 / PPT 翻页。
- 成片：9:16 竖屏 MP4，中文 TTS 旁白 + 烧录字幕，手机可直接播放与发布。
- 成片长度不设上限，以"讲清楚"为准；测试阶段先按 30-60 秒的短篇跑通流程。
- 两幕式流程，脚本确认是硬性关卡：**未经 Robert 确认不得开始花钱的视频生成**。

## 非目标（v1 不做）

- 背景音乐 / 音效（第一版只有旁白）。
- 自动发布到自媒体平台（成片给文件，发布 Robert 手动做）。
- 英文或双语版本。
- 真人出镜 / 数字人形象。
- 视频质量调优到商业级（本版目标是"跑通流程"）。

## 反目标（出现即失败）

- 科学性错误：给孩子讲错的知识，比"没有视频"更糟。
- 吓人或不适合儿童的画面（灾难、恐怖、暴力意象）。
- 跳过确认关卡直接烧钱生成视频。

## 已定的"怎么造"

这些是对话中 Robert 已拍板的决定：

| 决定 | 内容 |
|------|------|
| 形态 | Claude Code skill，放在 `RobertGate/.claude/skills/why-video/` |
| AI 服务 | **全部走 SiliconFlow 一个 key**（复用后端 `.env.local` 的 `LLM_API_KEY`）：脚本用 DeepSeek-V3、视频用 Wan 系列模型、旁白用 CosyVoice 系 TTS |
| 流程 | 两幕式：第一幕 研究+脚本+分镜 → 停下给 Robert 过目（可改旁白/画面/增删分镜）→ 第二幕 生成+合成 |

| 合成 | ffmpeg 本地拼接：片段时长向旁白音频对齐、烧录字幕、统一输出 9:16 MP4 |

## 流水线细节

### 第 0 步：能力验证（第一个交付物，我的默认决定）

动手搭流水线之前，先用现有 key 对 SiliconFlow 做一次冒烟验证：视频生成权限与余额、
可用的 Wan 模型清单、是否支持 9:16 竖屏、TTS 可用音色。
**验证不通过（无权限、无竖屏模型等）时停下向 Robert 汇报，建造者不得自行换供应商
或接受 16:9 裁剪之类的降级**——那些是 Robert 的拍板项。

### 第一幕：研究与脚本（免费、快）

1. **研究**：WebSearch 搜索问题的科学解释，至少两个来源互证；为儿童表达
   做"正确性损耗"检查（简化可以，简化到错不行）。
2. **写旁白稿**：讲故事体，先用孩子熟悉的事物引入（提问/场景），再层层解释，
   结尾一句温暖的总结或反问。长度由内容决定。
3. **拆分镜**：每个分镜 = {旁白词, 画面描述}。画面描述会被翻译成给视频模型的
   英文 prompt（视频模型对英文 prompt 效果更好——此为建造者可推翻的技术判断）。
   分镜画面需具体且儿童友好（示例：镜头低空掠过森林、沙漠、海洋，逐渐拉升到
   太空，露出蓝色圆形地球）。
4. **交付确认**：把 {旁白全文 + 分镜表 + 预估时长 + 预估生成耗时} 展示给 Robert，
   等待修改意见或确认。确认前不进入第二幕。

### 第二幕：生成与合成（花钱、慢）

5. **TTS 先行**：逐分镜生成旁白音频，得到每段真实时长——视频片段长度以此为锚。
6. **视频生成**：逐分镜调 SiliconFlow 视频生成接口（异步提交 + 轮询取结果），
   竖屏参数；单段生成失败自动重试，多次失败则暂停报告，已生成的片段缓存复用，
   避免重跑烧钱。
7. **合成**：ffmpeg 把片段与音频按分镜对齐（视频比旁白短则放慢/定格补齐，
   由建造者选实现），烧录字幕（旁白词按语音时长分行），拼接全部分镜，
   输出 `1080x1920 MP4(H.264 + AAC)`。
8. **交付**：成片 + 分镜中间产物存档到输出目录，向 Robert 报告路径、总时长、
   实际消耗（生成了几段、重试几次）。
9. **返工（v1 支持，我的默认决定）**：Robert 看成片后可要求"重做第 N 分镜"
   （可附新的画面描述）——只重新生成该分镜的片段，复用其余缓存，重新合成。
   为此 clips 目录按分镜粒度组织并带清单文件，合成步骤可重入。

### 成片画面审查（我的默认决定）

v1 不做自动的画面儿童友好检测（抽帧审查等）。确认关卡审的是文字（旁白 + 画面描述），
成片画面靠 Robert 人工把关，发现跑偏（如画面阴暗吓人）用上面的单分镜重做兜底。
分镜画面的英文 prompt 中统一加入明亮、温暖、儿童友好的风格词作为第一道防线。

### 模型档位（对话已有答案）

Robert 已拍板"先跑通流程"：默认选性价比档的视频模型，输出按模型原生分辨率
处理到 1080x1920（放大或补边由建造者定）。确认关卡展示本次成本预估，
Robert 可在那里否决。追求发布级画质是后续迭代的事。

### 产物目录（我的默认决定，可推翻）

```

├── script.md          # 旁白稿 + 分镜表（确认版）
├── clips/             # 各分镜视频片段 + 音频

```

## 约束

- SiliconFlow key 从 `backend/.env.local` 的 `LLM_API_KEY` 读取，不在 skill 文件中硬编码。
- 本机需有 ffmpeg（skill 启动时检查，缺失则给安装指引）。
- 视频生成是真实花费：除确认关卡外，skill 对单次运行的分镜数给出成本预估提示。
- 生成过程要可断点续跑：第二幕中断后重新运行，已完成的片段不重复生成。

## 留给建造者的

- SiliconFlow 具体模型选型与接口细节（Wan 哪个版本、T2V 还是 I2V、CosyVoice 哪个
  音色最像亲切的讲故事姐姐/叔叔）——以实现当天 SiliconFlow 实际可用清单为准，先验证再定。
- 分镜时长与视频模型单段时长上限（通常 5 秒左右）的匹配策略：一个分镜多段拼接
  还是放慢补齐。
- 字幕的分行与样式（可读性优先，儿童向大字）。
- skill 内部结构：SKILL.md 流程编排 + 独立 Python 脚本做生成/合成（建议，可调整）。
- 失败重试次数、轮询间隔等工程参数。
